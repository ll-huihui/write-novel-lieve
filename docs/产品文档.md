# AI 写小说直播工具 —— 产品文档

> 版本：v0.1（规划稿）
> 项目：write-novel-live
> 日期：2026-11-08

---

## 一、产品概述

### 1.1 定位

**"AI 作者现场写小说"的直播内容工具。** 观众观看一个 AI 以"人工打字"的方式一字一字写出小说，全程看着剧情从无到有；写作间隙 AI 主播与观众弹幕闲聊，观众还能影响剧情走向、用礼物触发剧情事件。

核心卖点：

- **悬念追更**：每段结尾留钩子，观众必须留下来看"接下来写什么"
- **真实感**：逐字打字机效果，像看一位作者现场码字，而非一次性贴出成品
- **参与感**：弹幕闲聊有来有回；投票和礼物能真正进入剧情素材

### 1.2 目标用户

| 角色 | 说明 | 使用的界面 |
|---|---|---|
| 主播 | 开播者。配置小说/模型/音色/互动规则，控制开写/暂停，必要时人工编辑正文 | 控制台页 + OBS 捕获直播页 |
| 观众 | 看直播写小说、发弹幕、投票、送礼物 | 直播平台（抖音等），通过直播画面看到稿纸 |
| 系统（AI） | 写作 AI（正文）、闲聊 AI（主播人格）、TTS 语音 | 后端服务 |

### 1.3 呈现形态

本地 Web 应用，浏览器打开两个页面：

- **直播页（stage）**：稿纸式写作界面，供 OBS 浏览器源捕获后推流到直播平台
- **控制台页（console）**：主播专用，与直播页完全分离，包含全部配置和开播控制

## 二、核心场景与用户故事

### 场景 A：开新书（开播前）

1. 主播打开控制台，点击"生成新书"→ **系统 AI 自动生成**书名、题材、人物卡、世界观、分卷大纲（主播无需填写；仍可手动修改后再开写）
2. 新书生成即带上**内容安全约束**：不得与网上已有作品雷同（不侵权）、不含敏感信息、不涉及政治 —— 写作全程持续遵守
3. 点击"生成开头"→ AI 依据设定卡写出第一章开头，**系统直接采用**（本版不做人工挑选）
4. 主播选择直播间房间号（对接 douyinLive），点击"开写"

### 场景 B：直播写作（核心循环）

1. 直播页稿纸上，AI 内容逐字出现（打字机效果，字速可配置）
2. 一段写完（段尾留钩子）→ 状态切换为"互动间隙"→ AI 主播读弹幕、闲聊回复（带语音）
3. 间隙定时结束或主播手动点"续写"→ AI 带着前文上下文续写下一段
4. 观众投票结果、高频弹幕建议作为"观众素材"注入下一次续写，但不直接决定剧情
5. 礼物触发预设剧情事件（如"神秘人物出场"），同样以素材方式注入

### 场景 C：章节流转

1. 章内字数达标且情节收束 → 系统判定章末 → 自动生成章末摘要入库
2. AI 依据大纲提议下一章主题，主播可在控制台修改后确认

### 场景 D：完结与归档

1. 主播（或 AI 到达自然终点时提议）发起"收官模式" → **系统校验总字数/章节数达标，不达标拒绝进入收官**
2. AI 收束伏笔、铺垫结局，生成结局章
3. 全书归档（只读、可导出 txt/markdown），主播开新书进入下一个循环

### 场景 E：人工接管

1. AI 输出跑偏时，主播暂停写作，直接在稿纸上编辑正文
2. 保存后继续续写，AI 以编辑后的文本为前文（不丢内容）

## 四、核心逻辑设计

### 4.1 写作状态机

```
                    ┌──────────────────────────────────┐
                    ▼                                  │
 [空闲] ──开新书──▶ [写作中] ──段落钩子完成──▶ [互动间隙] ─┘
                    │  ▲                         │
        主播暂停    │  │保存恢复                  │定时到/手动续写
                    ▼  │                         ▼
                 [已暂停]                    （回到 写作中）

 任意状态 ──主播发起/系统提议──▶ [收官模式] ──结局章完成──▶ [已完结]
```

| 状态 | 行为 | 直播页显示 |
|---|---|---|
| 空闲 | 无小说或未开播 | "新书待开"提示 |
| 写作中 | AI 流式续写，逐字推送 | 状态条"写作中"，稿纸逐字滚动 |
| 互动间隙 | AI 主播读弹幕、闲聊；定时器倒计时 | 状态条"互动中"，弹幕活跃 |
| 已暂停 | 打字队列与续写冻结；允许人工编辑 | 状态条"已暂停" |
| 收官模式 | 续写 prompt 切换为收束伏笔/结局导向 | 状态条"收官中" |
| 已完结 | 正文只读，可导出 | 完结页 |

**编辑冲突规则**：直播页编辑器获得焦点/控制台点"编辑" → 自动进入已暂停，打字队列冻结；保存后恢复之前状态。

### 4.2 上下文对齐机制（保证"不乱写"的核心）

每次续写组装的 prompt 结构（按预算裁剪）：

```
[系统] 你是一位小说作者，正在直播写作。只输出正文，禁止任何说明/标题/标注。
       段尾必须留悬念钩子。
       内容红线：不得抄袭/模仿任何已有作品；不含敏感信息；不涉及政治。
[设定卡] 书名、题材、人物卡（姓名/性格/关系）、世界观
[全书大纲] 若有大纲：当前章之后的走向；无大纲：剧情路线图（AI 定期生成/更新）
[前情摘要] 之前各章的摘要（章末自动生成入库）
[最近原文] 最近 N 段正文原文（保证文风与细节衔接）
[钩子衔接] 上一段的结尾钩子原文（新段落必须从这里接下去）
[观众素材] （可选）投票结果/弹幕高频建议/礼物事件 —— 供参考，不强制采用
[指令] 续写下一段，约 X-Y 字，结尾留钩子
```

**衔接校验**：续写完成后检查新段开头是否与上一段钩子语义衔接（首版用规则：新段不得重复钩子原文、不得出现"上一段/前文提到"类元话语；后续可加 LLM 校验）。不通过则重试一次。

**摘要生成**：章末判定触发 → LLM 生成本章 100-200 字摘要 → 存库，进入后续所有续写上下文。

### 4.3 输出清洗管道

```
模型流式输出 → 缓冲 → 段落级清洗 → 正文纯度校验 → 逐字队列
```

清洗规则：

1. 剥离 markdown 语法（`#`、`**`、`---`、列表符等）
2. 剥离常见元话语（"好的，以下是…"、"第X章（AI续写）"、括号注释、作者按语）
3. 剥离思考标记（`<think>…</think>` 等）
4. 段落纯度校验：中文占比、长度下限；不达标 → 整段丢弃重试（最多 1 次）

### 4.4 弹幕三条通路（互不污染）

| 通路 | 数据流 | 输出目标 | 关键约束 |
|---|---|---|---|
| ① 闲聊通路 | 弹幕 → 防注入过滤 → 闲聊 LLM（独立历史 deque）→ 气泡 + TTS | 直播页弹幕区气泡 | **绝不写入小说正文**；与写作 LLM 完全隔离（prompt/历史/配置各自独立） |
| ② 素材通路 | 投票结果、高频剧情建议 → 汇总器 | 续写 prompt 的"观众素材"字段 | 只供参考；主播可开关 |
| ③ 礼物事件通路 | 礼物 → 规则映射表（礼物/金额 → 事件文案）→ 汇总器 | 同上 | 冷却时间防刷屏 |

### 4.5 语音调度（全局互斥）

**硬规则：任何时刻全局只有一个语音在播放。**

```
[闲聊语音] ─┐
[正文朗读] ─┼─▶ voice_scheduler（单队列，优先级排序）─▶ 同一时刻最多 1 路播放
[提示音]   ─┘
```

- 优先级：礼物提示 > 正文朗读 > 闲聊（首版只有闲聊语音）
- 排队规则：高优先级插队到当前播放结束后；同级 FIFO
- 打断规则：仅"已暂停/系统事件"可打断当前播放，闲聊之间互相不打断（排队等）
- 队列上限（如 5 条），溢出丢弃最旧的低优先级条目，防积压

### 4.6 打字机渲染管线

```
后端清洗后的段落 → WS 推送 novel_delta 字符流 → 前端字符队列
  → 按字速（可配 80-150ms/字）逐字上屏 → 遇换行分段 → 页满自动翻页
```

- 主播控制：暂停（队列冻结）、跳过（快速放完当前段）、字速调节
- 页满翻页：稿纸按固定行数分页，写满自动翻页（翻页动画 P2 美化时加）

### 4.7 直播页 WS 推送协议（四类消息）

| 类型 | 方向 | 载荷 | 用途 |
|---|---|---|---|
| `novel_delta` | 服务端→页 | `{chapter_id, para_id, text, done}` | 逐字增量 |
| `danmaku` | 服务端→页 | `{nick, content, platform, type}` | 弹幕侧栏 |
| `chat_bubble` | 服务端→页 | `{text, voice_playing}` | 闲聊气泡 |
| `state` | 服务端→页 | `{state, chapter, para, timer}` | 状态条/间隙倒计时 |

页面重连后先发 `sync_request`，服务端回全量快照（当前章/段/状态/近几条弹幕），再继续增量。

## 五、界面与交互设计

### 5.1 直播页（stage）—— 给观众看，极简

```
┌─────────────────────────────────────────────┬──────────┐
│ 页眉：《书名》 · 第X章 章节名          [状态条]│  弹幕流   │
├─────────────────────────────────────────────┤          │
│                                             │ 弹幕滚动  │
│           稿 纸 主 区                        │          │
│   （作文纸/信纸质感，正文逐字出现）             │ [闲聊气泡]│
│                                             │ AI 回复   │
│                                             │          │
│                                             │ [投票卡片]│
└─────────────────────────────────────────────┴──────────┘
```

- 弹幕侧栏可折叠（主播在控制台控制）
- 状态条一行：`写作中 ▍` / `互动中 剩余 45s` / `已暂停`
- 稿纸支持鼠标滚轮/按钮翻页回看已写内容
- 本页**零配置入口**，所有控制都在控制台

### 5.2 控制台页（console）—— 给主播用，交互简单

- **开播三步**：① 选/建小说 ② 选直播间房间 ③ 点"开写"
- **小说管理**：卡片式书架（进行中/已归档）；书详情 = 设定卡表单 + 章节列表 + 大纲/路线图编辑
- **模型配置**：表单化 —— 写作模型一栏、闲聊模型一栏（provider 下拉：OpenAI 兼容/Ollama；base_url/key/model/温度）；"测试连接"按钮
- **语音配置**：音色库列表（名称/试听/启用），角色绑定下拉选择
- **互动配置**：投票开关与模板、礼物事件映射表（礼物→事件文案）、闲聊开关
- **保存即生效**：所有配置保存后立即热加载，无需重启

### 5.3 交互细节

- 编辑：点击稿纸正文进入编辑（自动暂停），Ctrl+S 或"保存"按钮恢复
- 字速滑杆在控制台"直播控制"区
- 投票发起：控制台选预设问题 → 直播页弹幕区上方出现投票卡片 → 倒计时结束出结果

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 模型输出跑偏/带出非正文 | 清洗管道 + 纯度校验 + 整段重试；正文与闲聊 LLM 完全隔离 |
| 内容侵权/敏感/涉政 | 生成与写作 prompt 红线 + 敏感词过滤管道（P2 加联网查重辅助） |
| 情节提前枯竭、几十章完本 | 篇幅目标硬校验（字数/章节数不达标禁止收官）+ 路线图按体量展开分卷弧线 |
| 剧情前后矛盾 | 摘要分层注入 + 钩子衔接校验；人工编辑随时纠偏 |
| 长篇上下文膨胀 | 摘要替代原文（只保留最近 N 段原文）；大纲/路线图压缩远景 |
| 弹幕提示词注入 | 正则硬拦截（复用 xiaoya engine.py 经验）+ 闲聊 LLM 红线 system prompt |
| API 限流/断流 | 流式重试；本地 Ollama 作为备用配置 |
| 语音混乱 | 全局单队列互斥调度器（硬性保证一路） |
